# LW-04：复用 Toonflow 原生 FFmpeg 自动出片

前置：LW-03已通过；Toonflow a4a96f1 / FlowKit 2da4b43。

方案：本地已审镜头清单 → 核对画布节点/Flow子任务/文件SHA → 原生FFmpeg → 本地MP4与导出清单。提供Toonflow本机自动化接口，后续文字模型可调用；不另建剪辑框架，不安装剪辑工具。文字模型仍为空，本卡不声称剧本自动创作已完成。

1. 导出请求必须含同一根任务、画布、明确顺序的至少2个不同视频节点及各自已验收hash；未完成/跨任务/重复素材/质量未确认全部拒绝。
2. 使用原生工作区路径权限和已配置system FFmpeg。首版仅静音8秒720p片段，输出顺序拼接，1280×720，时长=片段数×8秒。无需外部网站或模型。
3. 输入清单产生稳定exportId；状态和结果存同一工作区，重复调用读已有成片并校验hash，未完成或失败的旧导出不自动覆盖/重跑。
4. 测试非法路径、缺失镜头、hash不匹配、不同根任务、重复镜头、质量未确认、失败记录；类型与构建检查。
5. 真实验收：2个不同Omni镜头导出16秒本地MP4，可播放、无音轨、输出hash固定。重复调用不二次编码。保存0秒/7秒/8秒/15秒抽帧检查顺序；Seko关闭。
6. 提交仅本卡修改。整集、对白与自动质量判定仍LW-06；新标签/中断系统验收仍LW-05。

## 真实验收通过
2026-10-15：2个不同Omni镜头自动导出16秒1280×720、30fps、H264无音轨MP4（6622560字节）。原生文档树可打开并观察到12/16秒播放状态。0/7/8/15秒抽帧确认顺序；重复调用内容/mtime不变。7项非法输入拒绝+2项持久化状态注入拒绝通过，注入后原清单字节恢复；未模拟真实编码器故障。前后端检查依LW-03，本卡服务端类型检查及构建通过。
