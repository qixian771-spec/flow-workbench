# LW-03：Toonflow 原生 Omni 视频与同一本地项目续接

前置：LW-02真实生图已验收并提交 Toonflow 054c31c / FlowKit 1e1de94。

1. 原生视频节点增加唯一 Omni 模型：abra_i2v_8s、首帧图生视频、8秒、720p、横屏；文字模型不参与。本卡人工确认镜头提示词，固定加首帧连续性与静音约束，不声称自动拆镜或文字模型转换已完成。
2. 参考首帧读取工作区字节，SHA256必须匹配已完成本地Flow图片任务。保留原图片任务为rootJobId，在同一Flow工程与视频项目内创建视频镜头，禁止拿未知图片冒充已生成首帧。
3. 每个视频job输入与引用固定；提交前核对路由/首帧/提示词，保存真实Omni operation/model/duration/resolution回执；不重发未知请求，不切换模型。
4. 下载后校验真实回执身份、1280×720、8秒、视频编码与hash，再由原生generateMedia写回本地节点。根任务记录视频子任务及剪辑就绪状态。
5. 测试首帧篡改/不同job回执/错误路由/重复提交/未知提交/返回格式；原生前后端类型及构建通过。
6. 实测至少两个不同视频镜头，新视频产生、原生节点回填、刷新与同任务继续；明确是媒体链路验收，未配置文字模型和对白质量仍待后续卡。
7. 真实验收后提交；LW-04再串接本地自动剪辑，不混记为本卡已完成。

## 实测结果
两段不同运镜的真实Omni视频均8秒1280×720，原生节点回填、hash与Flow一致。首次第一镜头伞打开，人工抽帧检查判不合格；同Omni重做1次后已通过抽帧检查，旧结果保留但排除成片。源图任务→两条被接受视频子任务关系明确。服务重启和重复提交读取保持单个原请求。28项测试及前后端检查通过；不代表自动质量判断或对白验收。
