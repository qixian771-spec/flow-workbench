# 厂商 Skill → Flow 模型适配

日期：2026-10-13。本文先记录官方能力核对、链路审查和转换设计；下文“当前代码缺口”及任务卡保留该设计时点的状态。后续实施已将窄范围 v1 转换接入 Seko 常驻服务，完成 3 条真实视频对比及 v2 回填。功能已接通，质量提升尚未证实；v2 未设为默认。最新状态见 [实施与实测记录](SEKO-PROMPT-AB-TASKS.md)。

## 方案

保留官方和社区 Skill 的编导价值。先提取镜头意图，再按实际目标模型、版本、输入模式编译请求。平台名称不等于模型名称：本机 Seko 捕获中选中的模型是 `doubao-seedance-1-0-pro-fast-251015`，实际接管模型为 Flow `omni_flash`。这不代表所有 Seko Skill 都针对该 Seedance 版本。

流程：Skill 原始输出 → 镜头意图及不可变要求 → 目标能力检查 → 模型提示词与素材绑定 → 最终请求检查 → 生成 → 逐项验收 → 版本化经验记录。

不支持的要求必须明确停止并报告；不得删台词、缩短剧情、换模型或换厂商后当作同一任务成功。

## 已核对的差异

| 事项 | 官方依据或本机证据 | 适配决策 |
|---|---|---|
| 单镜头 | Omni 可能自行组织多个镜头 | 原始意图要求连续镜头时，显式写连续、无切镜；多镜头意图不得强制变成单镜头 |
| 图生视频 | Flow 建议文字补充参考素材，不与其冲突 | 参考图承担外观，文字重点表达动作、机位、情绪变化；不可删除图中未体现的剧情要求 |
| 事件时序 | Omni 支持自然语言或时间段，不要求唯一语法 | 保留本项目 0–3 / 3–6 / 6–8 秒习惯；它是本地约定，不是模型强制语法，也不保证逐帧准确 |
| 音频 | Omni 默认可能生成音轨 | 将生成对白、另配音对口型、无对白三种意图显式分开 |
| 固定音色 | Flow 文档提供 Omni 的 Voices，仅支持 Ingredients | 必须绑定真实音色引用；写“始终保持同一声音”不等于完成音色绑定 |
| 接口区别 | Gemini API 文档暂不支持上传音频参考；Flow UI 提供 Voices | 分别建能力记录，不把 Gemini API 的限制当成 Flow UI 的限制，也不照搬 API 标签到 Flow 的内部请求 |
| 负面要求 | Omni API 无独立负面提示字段，可在正文表达禁止事项 | 使用针对本镜头的自然语言限制；现有 `Negative:` 字符串只是正文，不是独立字段 |
| 语言 | Omni API 指南明确英语支持，其他语言尚未评估 | 可测试英文导演指令＋原文中文台词；不据此认定中文一定差，不翻译或润色要说出的中文 |
| 编辑提示词 | 官方对视频编辑建议聚焦修改项 | 仅用于编辑模式，不泛化成所有生成提示词越短越好 |

依据：[Omni 官方指南](https://ai.google.dev/gemini-api/docs/omni)、[Flow 创建视频与音色参考](https://support.google.com/flow/answer/16353334?hl=en)。这些资料给出功能与写法依据，不能替代当前账号可用性和成片质量实测。

## 当前代码缺口

- `scripts/seko_flow_job.py` 和 `scripts/libtv_flow_bridge.py` 将原始视频提示词直接写入 Flow 场景，尚无按模型转换。
- `agent/sdk/services/operations.py::_build_video_prompt` 给各模型共用 Veo 风格音频及 `Negative:` 追加逻辑；仅通过英文动词检测对白，中文“说”“问”不会触发角色声音说明。
- 无音乐且无 `Audio:` / `Music:` 标记时，项目 `allow_voice=false` 会追加仅环境音要求，可能与源提示词的对白冲突。不能仅检查转换后的正文，还要检查最终发给模型的文本和项目设置。
- `agent/services/omni_flash.py` 的 Ingredients 参数目前是图片引用，没有音色引用参数。
- FlowKit 底层已有多种视频模式；Seko 常驻接管只验收过横屏、720p、8 秒首帧路径。底层能力不等于桥接能力。
- 本地镜头与编剧 Skill 多处针对 Veo 3 编写，不应标成已经过 Omni 验证的最佳实践。

## 转换记录设计

每个镜头保存以下字段，原文与译文同时保留：

| 分组 | 内容 |
|---|---|
| 来源 | 平台、Skill 地址及版本、实际源模型、完整原文和哈希；手写输入明确标成手写 |
| 镜头意图 | 角色、动作及先后、景别、机位、视线、情绪转折、连续或切镜、时长 |
| 不可变内容 | 台词逐字文本、说话角色、顺序、音色绑定、参考素材对应关系、必要剧情事件 |
| 目标 | Flow 产品入口、实际模型键及版本、首帧/首尾帧/Ingredients/编辑、画幅、时长、分辨率 |
| 音频方案 | 模型原生对白，或明确的配音＋口型步骤；不得失败后静默切换 |
| 编译结果 | 转换正文、图片和音色绑定、最终请求文本、规则版本、每项改动理由 |
| 结果 | 生成任务、媒体、失败原因、画面及音频验收、成本证据；未知记未知 |

自由文本理解可由语言模型辅助，但不能把模型改写结果直接当作正确。确定性校验应检查台词未变、时间覆盖、素材存在、绑定身份、能力支持和设置一致。无法可靠解析的关键要求应留下待确认项，不能直接透传并声称适配成功。

## 真实输入对照：陈舟的反应镜头

来源：`output/seko-dialogue-20261013/native-generation-inputs-revised.json` 第二镜。这是此前代理填写并由 Seko 原站捕获的真实表单输入，**不是 Seko 厂商 Skill 自动产出**。

原始文本：

> 0-3s: Hold the front-facing close-up; the man lowers his eyes, lips closed. 3-6s: He lifts his gaze toward his companion just beside the camera, with a reluctant small nod. 6-8s: Hold a thoughtful expression. Locked camera, natural blinking, no talking, no music, no subtitles.

Omni 首帧模式候选文本（尚未生成对比）：

> One continuous 8-second shot with no cuts. Keep the front-facing close-up and locked camera from the supplied first frame. 0-3s: The man lowers his eyes, lips closed. 3-6s: He lifts his gaze toward his companion just beside the camera and gives a small, reluctant nod. 6-8s: He holds a thoughtful expression. He blinks naturally and does not speak. No music or subtitles.

转换只显式表达既有连续构图要求，并组织动作时序；保留低头、望向镜头旁同伴、勉强点头、若有所思，以及原有禁说话要求。未凭空添加运镜、外观、眼泪或新台词。

这里的禁说话来自原始任务，其后另有固定音色配音和口型。不能将该禁说话规则用于原生对白任务。

## 同一剧情若改用 Omni 原生对白

这是另一条明确的音频方案，不是上一段提示词的等价转换。剧本中陈舟原台词为“明天一早的车。”；如选择原生对白，需要保留这些字及说话角色，移除只属于另配音方案的闭嘴约束，并规划开口与停顿。提示词可明确“陈舟以普通话说：‘明天一早的车。’”，但不能据此认证发音逐字正确或音色稳定。

若同时要求固定音色，应走已核验支持的 Ingredients＋真实 Voices 绑定。当前 Seko 首帧桥接尚不能提交这个组合；须显式报告缺失，不能只添加 `@Voice` 文本冒充绑定。既有 Seko 固定音色＋口型流程仍是一个已实测的独立方案，不作为静默替代路径。

| P5 同素材生成对比 | 待实测 | 同一参考、模型、模式、时长、画幅及分辨率，原文与转换版分别生成；不承诺随机结果可精确复现 |
| P6 质量与成本验收 | 待实测 | 角色/事件/切镜检查、逐字听辨、音色和口型时序；记录失败与真实扣费，未计费证据则标未知 |

对比先覆盖静态文戏、情绪转折、走位和单人对白。至少分别检查多条镜头及重复样本，避免用一个好结果宣布“最佳提示词”。复杂动作只作为能力边界，不将其设为用户新增要求。

本轮文档验收：源文件与示例对照，区分官方说明、本机实测和待验证建议；检查修改差异后提交。运行服务、项目设置和已有生成任务未修改。
