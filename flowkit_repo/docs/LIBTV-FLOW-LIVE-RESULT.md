# LibTV × Flow 实测

日期：2026-10-13。沿用已有 LibTV CLI 1.1.3、FlowKit、FFmpeg 和 OiiOii 实测验收器，不新增安装。

结论：**LibTV 节点提示词 → 自有 Flow 真生成 → 上传 → 同节点回填 → 原站 CLI 合成 → 下载核验**已实测通过。原站生成按钮没有被拦截或替换；官方 CLI 将模型设为 `Flow` 被拒绝。不要将这两种接管混为一谈。

## 执行约束

- 禁止自动发布。生成后端为自有 Flow，不在接管失败时换用 LibTV 原生图像或视频模型。
- `video-clip --run` 是剪辑合成，不是生成模型；官方 CLI 同步等待终态，不额外轮询。
- 画布变更优先官方 CLI，网页用于可见结果验收及 CLI 未提供的入口调查。
- 凭据、带签名下载 URL 和厂商程序副本不提交。持久节点及时间线快照脱敏后保留。

## 关键发现：源节点实时解析，缓存仍需刷新

1. 先将真实 A URL 和媒体元数据写入既有 `video_generate` 节点；没有伪造任务完成状态，没有运行原生模型。
2. 建 `video-clip`，两个 Clip 的 `sourceNodeId` 均指向该节点，分别放在 0–8、8–16 秒，原声音量 1。
3. 把同一节点改为 B URL。`params.videoList[].url` 仍旧，两个 Clip ID 不变。
4. 直接合成 B：真实成片 4 秒和 12 秒均有蓝色顶栏，证明本测试的合成链按源节点读取新媒体。缓存陈旧仍判失败，不因成片正确而隐藏。
5. 用 `libtv node <合成节点> --left <源节点>` 再确认已有连线。没有重复建边，CLI 重算并更新 `params.videoList`，严格替换检查全部通过。

适配器规则：**回填源节点 → 显式刷新下游入边 → 重读快照 → 合成 → 下载检查**。不能只更新 `url` 就宣布工程完全一致。

## 生成接管的准确范围

`scripts/libtv_flow_bridge.py` 读取指定节点提示词，向本机 FlowKit batch API 提交真实请求；收集成功结果，下载并完整解码，再通过 LibTV 官方 upload 上传，将 URL 和 resourceMeta 写回同一节点。Flow 的待处理或失败状态不会被转为 LibTV 假完成。

实际运行 `libtv node <目标> -s model=Flow` 返回“未找到模型名字「Flow」”；没有调用原生生成。因此目前尚未验证原站 TV Director 自动产生任务后能被拦截，更没有改写网页“生成”按钮。目标节点原生模型字段仍是 Seedance 2.5，外部调度时不执行它；直接点原站生成按钮仍可能调用原生模型，不能当作 Flow 入口。

本轮由本代理串联明确的提交、收集、刷新、合成命令，已经是程序化接口链路；尚未交付一键输入完整剧本的无人值守工作台。固定音色、逐字台词、口型、角色一致性与完整 3–5 分钟成片仍未测。

## 已优化并记录的异常

- 创建带参考图的视频节点却保留默认纯文生模式，CLI 明确校验失败，未新建节点；查官方 schema 后显式设置单图模式，创建成功。只配置表单，不运行原生模型。
- A 原片第一次下载：CLI 水印接口 404，但仍返回文件且退出 0，实际文件与原片哈希相同。这个 API 异常保留；后续 A/B/新 Flow 成片下载均未出现该错误。桥接 CLI 包装器现在遇到 stderr 中的 API 错误即失败，不能以退出 0 覆盖错误。
- 本机 Python HTTPS 证书存储未找到下载站证书链，第一次收集停在下载前，未重复生成。现统一使用已有系统 `/usr/bin/curl` 的 HTTPS 证书验证完成下载；没有关闭证书验证、没有安装依赖。
- 状态文件在创建/提交/上传/回填前后持久化，同一状态文件加进程锁防止重复运行。遇到不确定的写入结果不自动重试；收集前后检查目标提示词与旧 URL，避免覆盖用户并发编辑。已完成状态重跑 collect 不再上传，实测返回 already_collected=true。不支持的时长、画幅或参考图数量直接报错。

## 复用和验证

- `platform_probe.py --provider libtv` 读取真实节点快照；片段的实际源 URL 与缓存源 URL 分开验收。支持本次单尺寸视频剪辑，混合尺寸或独立音轨明确拒绝，不能编造默认数据。
- `tests/test_platform_probe.py`：20 项，包括 OiiOii 真实陈旧引用、LibTV 真实缓存更新前后、音量、裁剪、缺失连线和歧义资源。
- `tests/test_libtv_flow_bridge.py`：10 项，包括待处理/失败时不上传、未知写入状态不重试、并发编辑保护、不支持的节点设置及退出 0 但 API 错误的拒绝。
- `docs/benchmarks/libtv-20261013/`：版本化证据。真实 CDN 地址替换为其 SHA-256 标识保留对应关系，原始响应只保留本机 output；没有凭据或签名 URL。
- 检查点通过不代表整体漫剧或三厂商比较完成；原生按钮接管保持未完成。

## 可重复调用

每次提交用新的 state 路径。`collect` 返回 3 表示仍在生成，返回 1 表示错误；由调度器之后再次收集，不重新 submit。

```bash
python3 scripts/libtv_flow_bridge.py submit \
  --project <LibTV画布ID> --node <指定视频节点ID> \
  --flow-project <Omni项目UUID> --reference-scene <已完成参考图的场景UUID> \
  --state <本次状态JSON>
python3 scripts/libtv_flow_bridge.py collect --state <本次状态JSON>
libtv node <合成节点ID> -p <LibTV画布ID> --left <指定视频节点ID>
libtv node <合成节点ID> -p <LibTV画布ID> --run
```

上述命令需使用真实已有 ID，不直接执行尖括号占位符。当前桥接器限定 8 秒、1280×720、Omni Flash、同一 Flow 项目中的已完成横屏参考图。
