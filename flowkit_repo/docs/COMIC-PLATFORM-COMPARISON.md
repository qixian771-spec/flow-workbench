# 漫剧平台工具对比与接入选型

核查日期：2026-10-13。公开资料覆盖十个平台；LibTV、OiiOii、Seko 均已登录实测 Flow 素材回填和原站出片。LibTV、Seko 另有真实 Flow 新生成回填；三家原生生成按钮均尚未接管。最新决策以 [三家真实结果](THREE-PLATFORM-LIVE-RESULTS.md) 为准。完整文戏、固定声音与口型仍未验收。

## 目标与方法

服务于横屏 3–5 分钟文戏漫剧：固定角色声音、精确台词、正面说话必须对口型；生成后端继续使用自有 Flow / Nano Banana 2.1 / Omni。

上一版对完整开源项目做了检索，但对商用网站工具比较不足，不能据此把 Flova 预定为首选。本次比较 10 个平台，按创作适配、外部素材流转、自动化入口、模型依赖四方面记录证据。功能存在不等于质量达标，文档描述不等于本机已验证。

## 对比矩阵

| 平台 | 已有资料显示值得复用的工具 | 外部素材 / 自动化证据 | 改接 Flow 的关键验证 | 在本项目中的候选角色 |

| OiiOii | 剧本、角色、场景、镜头、声音的创作流程；单镜修改与动画画布 [S2] | 官方 CLI 0.1.8 和桌面端 0.4.1 已安装；认证后图片/视频上传成功，原站 Agent 自动剪辑并渲染出 16 秒 MP4，下载解码通过。生成请求接管未测 | 能否锁定生成路线并取得镜头任务；导入音频是否能逐句绑定；3–5 分钟工程与跨镜一致性要实测 | 动画/漫剧主工作台候选 |
| Seko | 系列剧资产管理、角色/场景/道具关联、创作 Agent、画布与 Skills [S3] | 本轮实测原站模块支持同节点回填、指定分镜 REPLACE、渲染和状态查询；实际导出 16 秒文件，公开仓库仅作为源码线索 | 自有 SekoIDX / SekoTalk 能力与工作台绑定程度；换 Flow 后哪些资产约束仍生效 | 连载漫剧主工作台候选 |

| Katalist | 剧本拆场景/镜头、角色与地点卡、引用自动关联、Story Canvas、时间线 [S6] | 官方明确可把已有媒体拖入画布并导出时间线；本次未核验项目控制 API | 原媒体能否自动挂接现有镜头卡，而非仅落入素材区；中文对白和无人值守流程待测 | 分镜与资产组织主工作台候选 |
| Flova | 剧本、分镜、媒体、时间线、可复用 Skills、外部 Agent 项目操作 [S7] | 官方 CLI 支持项目、上传、状态、导出 | CLI 不证明自定义生成提供方；后台 Agent 是否仍触发原站生成、逐镜回填是否可控 | 主工作台与自动化接入候选之一 |
| Medeo | 对话式创作与已有素材驱动的视频生产 [S8] | 开发文档列出素材 URL 导入、创建任务、查询状态、渲染任务与用量接口 | 从提供素材到合成之间是否额外生成；精确镜头顺序、时长、对白能否保持 | 外部素材自动装配候选 |
| Higgsfield Popcorn | 连续分镜序列、逐帧导演、图像参考；官方帮助说明序列可再转视频 [S9] | 公开 API 支持媒体模型生成与文件上传 [S10]；不等于 Popcorn 工程 API | 分镜规划是否可独立获得；替换自有生成模型后序列一致性是否仍有效 | 分镜与镜头设计专用候选 |
| Runway | Apps / Workflows、Act-Two 表演驱动、关键帧、图像对白和视频编辑 [S11] | 可输入自己的素材；官方 Apps FAQ 明确 Apps 尚无 API | 表演迁移依赖其模型，不能直接换成 Omni 而宣称功能等价；常驻全自动接入待测 | 表演与对白专项对照，不预定整集主平台 |
| Boords | 剧本、分镜字段、镜头时长、版本、逐帧审阅、动态分镜预演 [S12] | API 可创建分镜、更新帧、上传外部图片；支持 Webhooks 与 MCP。API/连接处于 Beta [S13][S14] | 外部图片回填有明确文档；并未证明完整 Omni 视频剪辑工程能力。API 与 MCP 的套餐条件不同 | 可接入的前期分镜/审阅工具候选 |

“未核验”不代表没有该能力；“候选”不是已选用。以上商用平台不因为存在 API、MCP 或公开模型就被标称为开源软件。

## 选型判断

1. **中文漫剧优先考察 LibTV、OiiOii、Seko。** 依据是它们公开的创作工具与本任务贴近；这属于调研优先级，不是画面质量或接管成功率排名。
2. **镜头组织同时比较 LTX Studio 与 Katalist。** 横屏文戏需要能调整镜头、对白节奏和资产引用；不能只看是否有一键成片按钮。
3. **Flova、Medeo、Boords 提供不同类型的接入证据。** Flova 是工程操作入口，Medeo 是素材/创建/渲染流程，Boords 明确支持外部图片写入分镜。不能把三者统一记为“全部可换后端”。
4. **Higgsfield、Runway 按专用工具评估。** 某个镜头工具有价值不意味着整个平台适合作为工程中心；依赖它们模型的能力若需要使用，应作为明确的制作方案决定，不做 Flow 失败时的自动替代。

目标是选择一个主工程平台，再按实际需要配置少量专用工具。平台集合在规划阶段确定，执行时保持固定，不建立隐式自动切站。

## 三类工具必须分开

| 类型 | 例子 | 接到 Flow 后的预期 |
| --- | --- | --- |
| 工程管理工具 | 角色卡、分镜字段、素材引用、时间线、版本、审阅 | 最值得复用；需验证读写和媒体持久化 |
| 规划智能体 | 编剧、拆镜、导演、镜头提示词、自动剪辑规划 | 需验证是否允许只规划、是否能读取任务结果并继续 |
| 模型特有能力 | 身份保持、表演迁移、口型、局部重绘 | 不能因为保留界面就认为能力仍在；必须逐项测试并按所选制作方案实现 |

因此，“屏蔽生成接口”只是接入的一环。还要证明素材绑定、状态同步、工程保存和后续编辑能完整工作。

## 同题比较与验收任务

### R01：文档初筛（已完成）

输出本矩阵、来源和未知项。没有虚构数字评分，没有用官网案例作为本机实测。

### R02：真实工程比较（进行中，OiiOii 素材与成片链路通过）

用户已指定 LibTV、OiiOii、Seko。统一剧本为 [《雨停之前》](benchmarks/three-platform-script.txt)。已执行网页入口和官方工具检查，详情见 [实测记录](THREE-PLATFORM-LIVE-TEST.md)。OiiOii 已有真实工程并完成 16 秒素材链路测试，见 [结果](OIIOII-FLOW-LIVE-RESULT.md)；生成接管、文戏和三站比较仍未完成；不得因某站登录或接入方便就替它赢得创作能力评分。

统一测试包：同一份 30–45 秒双人中文文戏、相同画风与角色参考、固定声音样本、6–8 镜头目标；包含正反打、双人镜头、短句/长句、停顿、情绪转折和少量转头。复用相同的 Flow 素材验证回填，避免用各家原生模型效果替代接入比较。

逐站记录：

- 剧本：是否擅改台词，分镜是否保持角色与动作关系，镜头是否能独立修改。
- 资产：跨镜头是否引用同一角色/服装/声音版本；修改后依赖如何更新。
- 对白：能否指定逐句音频、匹配时长、指定说话人；正面口型是否可检验。
- 接管：生成提交是否可独立接收，原站未重复发起生成，状态和真实结果是否可回填。
- 持久性：刷新和重开项目后镜头与素材完整，导出引用正确版本。
- 自动化：逐镜手工步骤数量、请求数量、恢复点、错误可定位性。
- 成本：保留原站规划/存储/导出费用与 Flow 用量，单独记录语音/口型算力；不使用宣传最低价格代算整集费用。

每项仅记“通过 / 未通过 / 未测”，附工程或日志证据，不能用未测项得分。先通过台词保真、真实回填、持久保存和可自动继续四个门槛，再比较创作质量、人工步骤、维护量和费用。
