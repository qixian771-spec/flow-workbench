# 平台接入实测手册

## 本轮方案和任务卡

目标：从“新增素材能够成片”深入到“同一个素材节点更新后，原有剪辑是否更新”，并沉淀下一家可重复执行的验收流程。

| 卡片 | 执行 | 验收条件 | 状态 |
| --- | --- | --- | --- |
| R03-A | 在 OiiOii 原视频节点替换 B 版素材 | assetId 不变、URI 改变、下载哈希匹配 | 通过 |
| R03-B | 重新打开既有时间线 | 两个 clip 的 URI、ID、剪辑区间逐项比对 | 自动传播失败；显式更新片段通过；来源元数据未通过 |
| R03-C | 原站重新渲染 | 16 秒、音轨、完整解码及两个片段标记可见 | 通过 |
| R03-D | 离线验收器、失败用例及厂商记录模板 | 能拒绝陈旧引用、缺失片段和剪辑区间变化 | 通过，含真实快照回归测试 |

B 版是原 Flow 视频的本地可辨认变体：左右翻转、100 像素蓝色顶栏、8 秒、保留原音轨。它只验收素材替换，不计新模型生成或漫剧质量。

## 下一家固定顺序

1. 先检查已有官方 CLI、开放接口及 GitHub 仓库，记录版本、认证状态、能力边界；不要从手动页面点击开始。
2. 同一测试工程、同一份剧本、相同 A/B 素材。保留原文件 SHA-256。分开记录新建节点与替换既有节点。
3. 保存替换前的资产和时间线快照，明确目标 assetId、clipId、原 URI 与预期时长。
4. 执行一次真实替换，记录实际请求的端点与字段；不保存密钥、Cookie 或带签名 URL。
5. 重开工程核对持久化，再核对每个时间线引用。画布成功不代表时间线成功。
6. 若时间线仍引用旧素材，明确记录失败，单独执行引用更新，再重新验收；不得悄悄换回旧素材或平台模型。
7. 原站渲染后下载：检查时长、尺寸、音轨、完整解码、可辨认画面。只发起渲染或只看到成功提示不能通过。
8. 本轮任务测试、验收、提交。生成接管、对白、口型及整集验收独立，不用技术拼接样片代替。

## 证据级别

| 级别 | 含义 |
| --- | --- |
| 静态线索 | 官网、README 或客户端代码存在接口 |
| 请求成功 | 实际请求成功；尚未核对持久状态 |
| 持久化通过 | 重读或重开后 ID、URI、片段仍正确 |
| 成片通过 | 下载后媒体与画面检查均通过 |

## 记录模板

每家保留：版本、登录方式、工程 ID、源素材哈希、资产快照、时间线快照、导出文件哈希、检查报告、截图、失败原因、恢复步骤、未测能力。

## OiiOii 已遇到的操作细节

- 网页替换上传后调用 `/workspace/manage_assets`，使用 `update` 保留 assetId 并改变 URI；视频历史保存旧、新 URI。它不同于 CLI 上传后创建新 assetId。
- CLI `node update` 不支持任意 URI 或完成状态写入；不能将它当成媒体回填接口。
- Slate 对话输入必须触发真实输入事件，单改 DOM 文本不代表输入已被应用接收；检查“发送”按钮状态。
- 浏览器文件上传工具受扩展文件权限限制。本轮使用原生系统文件选择器；未改变扩展权限。进入“前往文件夹”后先确认文本框再填写完整路径，避免选中上一次目录。
- 客户端 MCP 配置保存、连接 listTools、Agent 实际调用是三项不同验收。当前只见到前两项的代码入口。
- 现有 FFmpeg 缺少 drawtext；可辨认素材直接使用蓝色实心顶栏，不为文字标记另装工具。

## 通用离线验收器

`scripts/platform_probe.py` 只读本地证据，不发起任何厂商请求。返回码 0 表示选定检查全部通过；返回码 1 表示失败或输入缺失。不得在失败时继续把任务标记为已接通。

OiiOii 直接读取官方 CLI 资产 JSON 与真实 `timeline/get` 响应。下一个厂商可以先导出以下 normalized 格式，复用同一验收器：

```json
{"assets":[{"id":"asset-1","uri":"new-media-uri"}]}
```

```json
{
  "id":"timeline-1", "duration_ms":16000, "aspect_ratio":"16:9",
  "source_uris":["new-media-uri"],
  "clips":[
    {"id":"clip-1", "uri":"new-media-uri", "start_ms":0, "end_ms":8000,
     "trim_start_ms":0, "trim_end_ms":8000, "volume":1},
    {"id":"clip-2", "uri":"new-media-uri", "start_ms":8000, "end_ms":16000,
     "trim_start_ms":0, "trim_end_ms":8000, "volume":1}
  ]
}
```

调用示例（替换路径为该厂商实际采集的文件）：

```bash
python3 scripts/platform_probe.py --provider normalized \
  --assets-before assets-before.json --assets-after assets-after.json \
  --timeline-before timeline-before.json --timeline-after timeline-after.json \
  --asset-id asset-1 --source replacement-b.mp4 --roundtrip downloaded-source.mp4 \
  --export rendered.mp4 --seconds 16 --size 1280x720 --blue-at 4 12 \
  --report acceptance.json
```

蓝色标记检测只用于本次测试素材，在两段中点采样，不能代替全片视觉验收。音轨存在及音量保留不等于声纹或口型通过。缺少来源引用的厂商需如实记录其不支持的能力，不得编造来源字段以通过检查。

## LibTV 实测新增规则

- 用 `--provider libtv` 复用验收器，输入格式为 `{"nodes":[源节点查询结果],"timeline":合成节点查询结果}`。真实快照见 `benchmarks/libtv-20261013/`。
- 更新源节点 URL 后，下游 `params.videoList` 可能仍旧；再次 `--left <已有源节点ID>` 可刷新缓存，不需要重新创建片段。B 版实际合成采用了新源视频，但缓存仍须独立检查。
- 不将“官方模型名字中没有 Flow”和“无法外部调度 Flow”混为一谈。外部桥接已真生成成功；原生生成按钮尚未接管，模型字段不会自动变成 Flow。
- CLI 退出码不能作为唯一成功条件。API 错误即使伴随退出 0，也保留失败记录并阻断自动继续。
- 生成失败、未完成、上传结果不确定与用户并发改动分别记录。只收集既有请求，不自动重提生成，不覆盖已变化的目标。
- 浏览器画布节点在视口之外时，先“适合屏幕”再打开预览；页面只用于可见验收，实际写入与合成均可由 CLI 完成。

## Seko 实测新增规则

- 已有官方公开仓库只提供策划/生成 API，不等于完整编辑器控制能力；先读当前已加载前端的实际请求封装。
- 同节点回填可用 `PUT canvas-node/{id}`，写入已上传的 `filePath` 与 `duration`；nodeId 保留，genId 更新。不要把 genId 更新当成节点重建。
- 已有分镜不随节点回填全部更新。`add-to-editor` 的 `REPLACE` 必须明确 shotId、seq、seqValue，之后逐条重新读取。
- 真实 `shots` 的时长单位为秒；媒体链接的签名参数会变化。比较对象路径，提交证据用路径散列，不把令牌变化算成新素材。
- Seko 快照没有与 OiiOii 同构的独立 sourceReferences，也没有本轮可核验的 volume 字段。使用 `scripts/seko_probe.py` 检查实际存在的音频开关，不伪造通用字段。
- `scripts/seko_browser_adapter.js` 在已登录、同源的开发者会话内执行，读取/回填/刷新/合成分别记录结果；不导出登录凭据、不持久修改原站按钮。构建版本变化直接报错。
- 关闭教学弹窗后必须刷新控件定位；一次陈旧索引误触音频分离已记录，不计入生成接管证据。批量变更使用接口后仍须重开工程做可见核验。
- 当前上传使用已有浏览器的系统文件选择器自动化；未经授权不修改扩展文件权限。原站自动下载的客户端阻止与服务端渲染成功分别记录。
