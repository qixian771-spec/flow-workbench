## 第一版边界

`seko-omni-first-frame-silent-v1` 是保留原文的规则适配，不是任意剧本的语义重写器。先支持显式无对白、无音乐、固定机位和 0–3 / 3–6 / 6–8 秒的镜头。转换添加连续无切镜和首帧构图约束，原始动作段落逐字保留。其他模式、对白、切镜、运镜或时序不明确时停止，不直接透传。

两版都使用同一个新的 Omni 最终提示词构建器，排除旧 Veo 模板干扰；A 为原文，B 为转换文。这是对转换增量的比较，不是同时改变模型、图像或后处理。原始句子已经较完整，允许观察结果为“两者无明确差异”，不预设 B 获胜。

运行时在付费提交前记录最终 provider 参数和文本哈希。`prepared` 只代表准备提交，必须另有远端任务和成片证据才能算生成成功。

2. 首次预检查因手工输入参考场景 UUID 拼写错误返回 404，在创建状态文件和生成任务前停止；修正为已知 UUID 后才提交，没有因此产生重复消耗。
3. A/B 视频集合 `3807b07f-d9a6-48ef-99fb-3cc70c3704da` 一次批量创建两个真实任务。A：`cea1654b-6a7e-42bb-9d63-3df9e7826757`；B v1：`d0f1c6c1-4bf9-4b3b-87a0-41660e94a130`。两个结果都为 1280×720、8 秒，完整解码通过，独立媒体 ID 与哈希不同。
4. 最终 provider 参数核验了相同参考 UUID `85966991-65ac-490e-a653-cf16b9a312cf`、项目、Omni、首帧模式、8 秒、720p、横屏。文字与期望编译结果相符。A/B 共用新的 Omni 最终构建器；这不是旧 Veo 构建器与新构建器的混合比较。
5. v1 在约 5–5.5 秒有张嘴动作。因此加入实验 v2 的全程闭口约束，保持所有原文字节和动作顺序。该补测来自 Seko 页面已有的常驻 `enqueue` 入口，沿用原始捕获输入；不是额外安装脚本或手工上传替代结果。
6. v2 常驻任务 `ef81c323-a80d-44cb-bdef-abbe45d313e2`、Flow 请求 `03a42a44-aac3-47ea-8a3e-71d1288257c8` 成功；自动下载、哈希检查、上传、原站检查、回填均完成。Seko 新节点 `2110224776686592002`；刷新后页面显示 5 个完成、1 个待检查。待检查仍是此前的旧超时任务，本轮 3 个生成均成功。
7. v2 仍在约 2.5–4.5 秒出现张嘴。三版统一按每秒 2 帧检查：人物与咖啡店延续参考，未见明显切镜，均有低头和抬眼；轻点头没有独立量化。原文版本在所抽帧中未见明显张嘴，但只有每种提示词一个样本，不能排除随机差异，不能宣称普遍优劣。
8. v2 保留为可显式选择的实验规则，不设为常驻默认。默认继续采用 v1 的保守、保留原文转换；它的功能已验证，但画面更优没有验证。无失败后自动换回原文生成、换模型、换厂商或再次付费的逻辑。
9. 审查时保留了 Omni 原有可用的角色声音描述上下文；它仍不等于真实音色绑定。本轮是静默反应镜头，不把它当作固定音色、逐字对白或口型验收。
